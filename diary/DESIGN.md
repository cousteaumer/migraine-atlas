# Дневник мигрени: проект

Черновик архитектуры. Что записываем, как храним, когда и где спрашиваем.
Пороги и формулировки взяты из вики атласа (статьи `triggery`, `izbytok-lekarstv`,
`profilaktika`, `faza-boli`, `okonchanie-pristupa`, `sensitizaciya`).

## 1. Принципы

1. **Два потока данных.** Ежедневный фон (одинаковый каждый день, даже без боли)
   и приступ (отдельная сущность с фазами и событиями по ходу).
2. **Журнал событий, а не анкета.** Источник истины — append-only список событий
   с меткой времени. «День» и «приступ» — представления, которые считаются из событий.
   Так можно дописывать по ходу («боль началась», «принял таблетку», «помогло»),
   править задним числом и ничего не терять.
3. **Минимум нажатий.** Во время приступа экран режет глаза. Ежедневный опрос —
   до 8 нажатий, без набора текста. Приступ — большие кнопки, по одному вопросу.
4. **Пропуск — это тоже данные.** Незаполненный день помечается явно,
   чтобы статистика не считала его «днём без боли».
5. **Данные принадлежат пользователю.** Экспорт в JSONL и CSV одной командой,
   удаление всего — тоже одной командой.

## 2. Формат хранения

### 2.1. Событие

Одна запись = один JSON-объект, по строке в файле `*.jsonl` (или строка таблицы `events`).

```json
{"id":"01J9ZK...","ts":"2026-10-16T21:40:12+03:00","kind":"day.checkin","date":"2026-10-16","data":{...}}
```

| Поле      | Что это                                                             |
|-----------|---------------------------------------------------------------------|
| `id`      | ULID: сортируется по времени, уникален без координации              |
| `ts`      | Момент записи, ISO 8601 **со смещением** (часовой пояс важен для сна) |
| `at`      | Момент, к которому относится событие, если он отличается от `ts` (записал задним числом) |
| `date`    | Локальная календарная дата, к которой относится событие             |
| `kind`    | Тип события, см. ниже                                               |
| `attack`  | id приступа, для событий приступа                                   |
| `data`    | Полезная нагрузка, зависит от `kind`                                |
| `edits`   | id события, которое эта запись исправляет (старое не удаляется)     |
| `src`     | откуда пришло: `tg-bot`, `tg-app`, `web`, `import`                  |

### 2.2. Ежедневный фон: `day.checkin`

```json
{
  "sleep":   {"bed":"01:10","wake":"08:30","awakenings":1},
  "meals_skipped": 1,
  "alcohol": {"yes":true,"kind":"red_wine"},
  "stress":  {"level":2,"ended":false},
  "neck":    true,
  "cycle_day": 14,
  "meds":    [{"drug":"ibuprofen","dose_mg":400,"class":"nsaid"}],
  "verdict": "migraine",
  "note":    "..."
}
```

- `stress.level` 0–3. `stress.ended: true` означает «напряжённый период сегодня закончился»
  (в вики: пик уязвимости через 6–18 часов после).
- `verdict`: `none` | `headache` | `migraine` | `unknown`. Если `migraine`, а открытого
  приступа нет, бот создаёт приступ задним числом и задаёт 4 вопроса (см. 3.3).
- `meds` здесь дублируют события `attack.med`, если приступ вёлся по ходу; при подсчёте
  дней с лекарствами берётся объединение по дате.
- Отдельное событие `day.skipped` с `date`, если опрос остался без ответа.

### 2.3. Приступ: события с общим `attack`

| `kind`               | `data`                                                                  |
|----------------------|-------------------------------------------------------------------------|
| `attack.open`        | `{"first_symptoms":["fatigue","yawning","neck","fog","craving","photophobia","mood"], "at":...}` |
| `attack.aura`        | `{"types":["visual","sensory","speech"],"minutes":25,"side":"left","gradual":true}` |
| `attack.pain.start`  | `{"intensity":2,"side":"right","location":["eye","temple"],"pulsating":true,"worse_move":true}` (intensity 1–3: слабая/умеренная/сильная, либо 0–10) |
| `attack.pain.update` | `{"intensity":3}`                                                       |
| `attack.symptoms`    | `{"nausea":true,"vomiting":false,"photo":true,"phono":true,"osmo":false,"allodynia":"scalp"}` (`none`/`scalp`/`beyond_head`) |
| `attack.med`         | `{"drug":"sumatriptan","dose_mg":50,"class":"triptan","allodynia_at_intake":false}` |
| `attack.med.effect`  | `{"med":"<id события med>","after_h":2,"effect":"free"}` (`free`/`better`/`none`) |
| `attack.pain.end`    | `{"how":"sleep"}` (`sleep`/`vomit`/`med`/`self`/`unknown`)              |
| `attack.recurrence`  | `{"within_h":48}` — боль вернулась, считается тем же приступом           |
| `attack.close`       | `{"back_to_normal":true}` — конец постдрома                              |
| `attack.cancel`      | открыли по ошибке                                                       |
| `note`               | `{"text":"..."}` или `{"voice":"file_id"}` — свободная заметка           |

Классы лекарств (для порогов избытка): `nsaid`, `paracetamol`, `triptan`, `gepant`,
`combo` (с кофеином/опиоидом), `opioid`, `ergot`, `other`.

### 2.4. Профиль: `profile.set`

Часовой пояс (IANA), время опросов, есть ли цикл, список «своих» лекарств с дозами
(чтобы кнопки были именно с ними), текущая профилактика
(`{"drug":"...","dose":"...","since":"2026-09-01","schedule":"daily"}`), возраст аур.

### 2.5. Производные представления (считаются, не хранятся)

- **День**: дата → фон + список приступов, пересекающих дату + дни с лекарствами по классам.
- **Приступ**: времена фаз (продром → аура → боль → постдром), длительность боли,
  максимальная сила, была ли аллодиния и когда, лекарства и их эффект, чем закончился.
- **Месяц**: дни мигрени, дни головной боли, дни с лекарствами по классам,
  доля дней «в какой-либо фазе», число незаполненных дней.
- **Предупреждения**: средства от приступа чаще 2 дней в неделю; 10+ дней триптанов /
  комбинированных / опиоидов или 15+ дней простых обезболивающих за месяц;
  15+ дней боли в месяц три месяца подряд при 8+ мигренозных; красные флаги
  (аура дольше часа, слабость, боль «ударом грома», аура впервые без боли).

### 2.6. Где лежат файлы

- Рабочее хранилище: SQLite (таблица `events` + индексы по `date`, `attack`) на сервере бота.
- Экспорт: `diary/data/YYYY-MM.jsonl` + `YYYY-MM.csv` (по дню) + календарь для невролога.
- **Важно:** репозиторий `migraine-atlas` публичный и опубликован на GitHub Pages.
  Медицинский дневник сюда класть нельзя. Варианты: отдельный приватный репозиторий
  `migraine-diary-data`, куда бот коммитит экспорт раз в сутки, либо только сервер + экспорт
  по запросу. Код бота и приложения можно держать здесь, данные — нет.

## 3. Когда и что спрашивать

### 3.1. Ежедневный опрос (вечер, время настраивается, по умолчанию 21:30)

Одно сообщение, вопросы по очереди, каждый ответ — кнопка:

1. «Как спалось прошлой ночью?» → лёг (сетка 21:00…03:00 с шагом 30 мин, «как обычно»),
   встал (аналогично), пробуждения (0 / 1 / 2+).
2. «Пропускал еду?» → нет / 1 / 2+.
3. «Алкоголь?» → нет / пиво / вино / крепкое / красное вино.
4. «Стресс сегодня?» → 0 / 1 / 2 / 3, затем «напряжённый период закончился?» да/нет
   (только если вчера или сегодня уровень ≥ 2).
5. «Шея болит или скована?» → да / нет.
6. «День цикла?» → число или «не применимо» (бот сам считает от последней отметки
   начала и просто просит подтвердить).
7. «Что-то принимал от головы?» → нет / кнопки с «моими» лекарствами.
8. «Голова сегодня?» → не болела / болела, не мигрень / мигрень / не знаю.

Повтор одного раза через 2 часа, если нет ответа. В 04:00 следующего дня — `day.skipped`.
Утренний вариант (сон спрашивается точнее, остальное про вчера) — настройкой профиля.

### 3.2. Приступ по ходу

Старт — кнопка «Начинается» в постоянной клавиатуре бота или команда `/attack`.
Дальше бот ведёт сам:

| Момент                        | Вопрос                                                     |
|-------------------------------|------------------------------------------------------------|
| сразу                         | «Что чувствуешь?» мультивыбор из 7 предвестников; «Аура есть?» |
| если аура                     | тип (мультивыбор), сторона; через 60 мин: «прошла?» (если нет → красный флаг) |
| «Боль началась»               | сила, сторона, место, пульсирует, хуже от движения, спутники, аллодиния |
| каждые 4 ч, пока боль открыта | «Боль сейчас?» нет / слабая / умеренная / сильная          |
| «Принял лекарство»            | кнопка с «моим» списком; «кожа головы уже болезненна?»     |
| через 2 ч после лекарства     | «Помогло?» нет боли / легче / не помогло                   |
| «Боль прошла»                 | «Чем закончилось?» сон / рвота / лекарство / само          |
| утро после конца боли         | «Голова уже своя?» да / ещё нет (повтор раз в сутки, до 48 ч) |
| 48 ч после конца боли         | «Боль возвращалась?» да / нет → `recurrence` или `close`   |

Между опросами бот молчит. Любой вопрос можно отложить кнопкой «позже» (повтор через час).

### 3.3. Приступ задним числом

Если в вечернем опросе выбран «мигрень», а приступа нет: «Когда началась боль?»
(сетка часов), «Сила?», «Что принимал?», «Прошла?» — четыре вопроса, остальное
можно дописать в приложении.

## 4. Платформа

### 4.1. Выбор

**Telegram-бот + Mini App.** Причины:

- доставка опросов — задача Telegram, не нужны веб-push (на iOS они ненадёжны);
- кнопки под сообщением закрывают ежедневный опрос целиком, без форм;
- Mini App (обычная HTML-страница внутри Telegram) — для приступа с ползунками,
  календаря, истории и экспорта; та же страница открывается и в браузере;
- стиль и тексты можно взять из атласа, а поля формы ссылать на статьи вики.

### 4.2. Серверная часть

Рекомендация: **Cloudflare Workers + D1 (SQLite)**. Бесплатного плана хватит
на одного-нескольких пользователей, нулевое администрирование.

- вебхук Telegram → Worker: обработка кнопок, запись событий;
- cron-триггер раз в 5 минут: смотрит таблицу `followups (user, due_at, kind)` и шлёт
  то, что пора (вечерний опрос, «помогло?», «боль сейчас?»); расписание хранится
  в UTC, считается из часового пояса профиля;
- Mini App раздаётся тем же Worker'ом или с GitHub Pages (`/diary/app/`), авторизация
  по `initData` Telegram.

Альтернатива, если захочется Python: `aiogram` + SQLite + APScheduler на маленьком VPS.
Логика и схема те же, только нужен хостинг и его обслуживание.

### 4.3. Что лежит в этом репозитории

```
diary/
  DESIGN.md          этот документ
  schema/            JSON Schema событий + примеры (следующий шаг)
  app/               Mini App: index.html, работает и без Telegram
  worker/            бот: вебхук, cron, D1-миграции
```

Данные — не здесь (см. 2.6).

## 5. Порядок работы

1. Схема событий как JSON Schema + «образцовая неделя» с двумя приступами, чтобы на ней
   проверить расчёт дней и предупреждений.
2. Скрипт расчёта представлений (день / приступ / месяц / предупреждения) — на Python,
   как `build.py`, чтобы проверить формулы на образце.
3. Mini App: форма приступа и календарь; хранит в localStorage, экспорт JSONL.
   Уже этим можно пользоваться без бота.
4. Бот: вечерний опрос и запись в D1.
5. Бот: ведение приступа по таймерам (раздел 3.2).
6. Экспорт для невролога: месячный календарь одним экраном и CSV.
